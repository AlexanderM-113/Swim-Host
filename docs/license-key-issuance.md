# SwimManager Pro — License Key Issuance Guide

This guide covers every step from generating a key to handing it to a customer, tracking activations, and revoking access when needed.

---

## Prerequisites

Before issuing any key, confirm you have:

| Item | Value |
|---|---|
| Worker URL | `https://swimmanager-license.fhardy25.workers.dev` |
| Admin Secret | The password you set as the `ADMIN_SECRET` environment variable in Cloudflare |
| HTTP client | Cloudflare dashboard tester (easiest), Hoppscotch, Insomnia, or curl |

---

## Step 1 — Choose a Key Format

Keys follow this pattern: **`SWIM-XXXX-XXXX-XXXX-XXXX`**

Each block is 4 alphanumeric characters. Examples:

```
SWIM-AB12-CD34-EF56-7890
SWIM-PREM-2026-SHKS-0001
SWIM-GOLD-MAST-ERSC-OAH1
```

**Tips:**
- Use a block that identifies the tier: `PREM`, `STAR`, `BASI`
- Use a block that includes the year: `2026`
- Use a short club code: `SHKS` for Sharks, `WAVE` for Waves SC
- Last block = sequential number so you can track batches

You can generate random keys at https://www.guidgenerator.com or just type them manually.

---

## Step 2 — Create the Key via API

### Using the Cloudflare Dashboard (Recommended)

1. Go to **dash.cloudflare.com** → Workers & Pages → `swimmanager-license` → **Edit Code**
2. In the right panel, open the **HTTP tester**
3. Configure the request:

```
Method:   POST
URL:      https://swimmanager-license.fhardy25.workers.dev/admin/create

Headers:
  Content-Type    application/json
  X-Admin-Secret  <your admin password>

Body:
{
  "key":       "SWIM-PREM-2026-SHKS-0001",
  "clubCode":  "sharks",
  "clubName":  "Sharks Swim Club",
  "tier":      "pro",
  "expiresAt": "2027-06-01"
}
```

4. Click **Send** — you should receive:
```json
{ "ok": true, "key": "SWIM-PREM-2026-SHKS-0001" }
```

### Using curl (terminal)

```bash
curl -X POST https://swimmanager-license.fhardy25.workers.dev/admin/create \
  -H "Content-Type: application/json" \
  -H "X-Admin-Secret: YOUR_ADMIN_PASSWORD" \
  -d '{
    "key": "SWIM-PREM-2026-SHKS-0001",
    "clubCode": "sharks",
    "clubName": "Sharks Swim Club",
    "tier": "pro",
    "expiresAt": "2027-06-01"
  }'
```

### Field Reference

| Field | Required | Notes |
|---|---|---|
| `key` | Yes | The license key string in `SWIM-XXXX-XXXX-XXXX-XXXX` format |
| `clubCode` | Yes | Short lowercase identifier, no spaces (`sharks`, `wavesc`, `bluefins`) |
| `clubName` | Yes | Full club name for display in the app |
| `tier` | Yes | `starter`, `pro`, or `enterprise` |
| `expiresAt` | No | ISO date `YYYY-MM-DD`. Omit for perpetual license. |

## Step 4 — Verify the Key Was Stored Correctly

List all issued keys:

```bash
curl -X GET https://swimmanager-license.fhardy25.workers.dev/admin/list \
  -H "X-Admin-Secret: YOUR_ADMIN_PASSWORD"
```

Response:
```json
{
  "ok": true,
  "keys": [
    {
      "key": "SWIM-PREM-2026-SHKS-0001",
      "clubCode": "sharks",
      "clubName": "Sharks Swim Club",
      "tier": "pro",
      "expiresAt": "2027-06-01",
      "activatedAt": null,
      "activations": 0
    }
  ]
}
```

`activatedAt` will populate once the customer activates from within the app. `activations` tracks how many times the key has been used (useful if you want to enforce machine limits later).

---

## Step 5 — Customer Activates the Key

When the customer enters the key in Settings → License, the app calls:

```
POST /activate
Body: { "key": "SWIM-PREM-2026-SHKS-0001", "machineId": "<auto-generated>" }
```

The Worker validates the key, checks expiry, and returns:
```json
{
  "ok": true,
  "clubName": "Sharks Swim Club",
  "tier": "pro",
  "expiresAt": "2027-06-01"
}
```

The app stores the result locally and unlocks full access.

---

## Revoking a Key

If a customer cancels, disputes a charge, or you need to disable access:

```bash
curl -X POST https://swimmanager-license.fhardy25.workers.dev/admin/revoke \
  -H "Content-Type: application/json" \
  -H "X-Admin-Secret: YOUR_ADMIN_PASSWORD" \
  -d '{ "key": "SWIM-PREM-2026-SHKS-0001" }'
```

Response:
```json
{ "ok": true }
```

The key is deleted from the KV store. On the customer's next online check, the app will report the license as invalid.

---

## Issuing a Replacement Key

If a customer loses their key or needs a fresh one (e.g., you revoked the old one):

1. Revoke the old key (above)
2. Create a new key with a new `key` string but same club info
3. Email the new key to the customer

## Tiers

| Tier | Intended Use |
|---|---|
| `starter` | Small clubs, basic features only |
| `pro` | Full feature access — Meet Manager, Workout Manager, Team Manager, Scoreboard |
| `enterprise` | Multi-club, white-label, or custom integrations |

Tier enforcement in the app is done by checking `license.tier` in the license context. Update the `LicenseGate` component to restrict features per tier as needed.

## Security Notes

- **Never share your `ADMIN_SECRET`** — it grants full control to create and revoke keys
- Store `ADMIN_SECRET` in your password manager, not in a text file
- Cloudflare KV has 99.9% uptime SLA — keys are globally distributed
- If you suspect your `ADMIN_SECRET` is compromised, rotate it immediately in Cloudflare Workers → Settings → Variables
