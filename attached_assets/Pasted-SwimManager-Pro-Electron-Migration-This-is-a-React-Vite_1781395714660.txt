SwimManager Pro — Electron Migration

This is a React + Vite frontend (port 21868) + Express 5 API (port 8080) + PostgreSQL via Drizzle ORM, structured as a pnpm monorepo. The frontend currently stores all data in localStorage via artifacts/swim-manager/src/lib/local-store.ts— the Express API exists but is not used for primary data storage.

Prepare this codebase for packaging as a standalone Windows Electron .exe. Make the following changes:

local-store.ts — Replace all localStoragereads/writes with fetch calls to the Express API (/api/...). The React Query hooks must keep the same signatures. Use the already-generated hooks in lib/api-client-react/src/generated/api.tsas the new data layer.

artifacts/api-server — Swap the Drizzle database driver from drizzle-orm/node-postgresto drizzle-orm/better-sqlite3. The schema in lib/db/src/schema/ is unchanged. The SQLite file path should resolve to {userData}/swimmanager.db using a path passed via environment variable SQLITE_PATH.

New electron/main.ts — Electron main process that: (a) reads a club config from {userData}/club-config.json; (b) validates a license key via electron/license.ts; (c) spawns the bundled Express API as a child process; (d) opens a BrowserWindow loading the built Vite static files.

New electron/license.ts — Offline HMAC-SHA256 license key validator. Key encodes: clubName, clubCode, expiresAt, tier. On first run, optionally POST to a configurable activation URL.

New electron/club-config.json schema — { clubName, clubCode, licenseKey, apiHost, liveRelayUrl }. apiHost defaults to "localhost" but can be set to a LAN IP for multi-seat use (secondary machines point at the primary's IP).

vite.config.ts — Add a production static build mode (vite build) targeting dist/. The dev proxy (/api → localhost:8080) is replaced by Electron's apiHost config at runtime.

lib/live-push.ts — Change the push target from relative /api/live/:meetId to {liveRelayUrl}/api/push/{clubCode}/{meetId}read from club config.

Do not change any React component files. Do not change lib/db/src/schema/. All UI, hooks, and API route handlers remain unchanged.
